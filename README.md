# Aggratech

**Проверка навыков. Поиск специалистов. Контакты по согласию.**

Кандидат подтверждает Backend Junior или Middle заданиями на Python и SQL,
публикует результат и получает предложения. Компания ищет специалиста по
навыкам и условиям работы, видит объяснения подборки и размещает вакансии.
Контакты открываются выбранной компании по разрешению кандидата.

[Руководство для жюри — PDF](docs/submission/01_jury_guide.pdf) ·
[API и зависимости — PDF](docs/submission/02_api_reference.pdf) ·
[Перечень сдачи — PDF](docs/submission/03_submission_checklist.pdf)

## Запуск одной командой

Нужны **Docker Engine с Linux-контейнерами и Docker Compose**. Для исполнения
решений требуются cgroup v2 и seccomp; при первой сборке — интернет.
Python, Node.js, отдельная VM и GPU на компьютере жюри не нужны.

Из корня репозитория:

```bash
docker compose up --build -d --wait --wait-timeout 1800
```

| Открыть | Адрес |
|---|---|
| Приложение | **http://localhost:18000** |
| Почта подтверждения и уведомления, Mailpit | **http://localhost:18025** |
| Интерактивный API | http://localhost:18000/docs |
| Схема OpenAPI | http://localhost:18000/openapi.json |

Первый запуск собирает интерфейс, применяет миграции и оценивает решения
стартовых кандидатов. Подождите завершения команды: это занимает несколько
минут. Параметр `1800` ограничивает ожидание готовности, а не задаёт время теста.

Вы получите **12 кандидатов, 3 компании, 9 вакансий, 15 приглашений,
18 откликов и 3 непустые подборки**. Повторный запуск не создаёт дубликаты,
не сбрасывает пароли и не затирает пользовательские изменения.

| Работодатель | `employer01@aggratech.example.com` | Линия данных: подбор, вакансии, предложения |
| Работодатель | `employer02@aggratech.example.com` | Городские сервисы: отдельные согласия |
| Работодатель | `employer03@aggratech.example.com` | Финтех решения: вакансии и отклики |

Например, второй кандидат — `candidate02@aggratech.example.com`.
Биографии вымышлены; уровни получены настоящим оцениванием решений движком v3,
а не ручной записью баллов. Эти аккаунты не включаются в статистику людей.
Профили без ФСП участвуют в поиске на обычных основаниях.

Для собственного прохождения зарегистрируйте **нового кандидата**, подтвердите
email через Mailpit и заполните профиль. У стартовых кандидатов проверка уже
пройдена; для них действуют ограничения повторных попыток.

## Что проверить в интерфейсе

| Кандидат | Работодатель |
|---|---|
| Профиль и приватность имени/контактов | Профиль компании |
| Выбор Junior/Middle, Python/SQL, черновики и таймеры | Потребности и три редактируемых шаблона |
| Результат с причинами, история и публикация | Подбор по навыкам, условиям и приоритетам |
| Предложения от компаний и выбранные контакты | Сравнение двух кандидатов и объяснения |
| Вакансии, отклики и отзыв | Приглашения с обязательной зарплатой |
| PDF с кириллицей и текущей приватностью | Создание, изменение и закрытие вакансий; отклики |

Для сквозной проверки откройте кандидата и работодателя в разных браузерных
профилях. Отправьте предложение, разрешите только email и проверьте, что телефон
остаётся закрытым. Затем отзовите разрешение и скачайте новый PDF.
Отзыв одного отклика не закрывает контакты, разрешённые другим действующим
источником. Уже скачанный файл удалённо отозвать невозможно.

Опрос не присваивает уровень. В проверке навыков пять заданий части A
(до 30 минут) и два части B (до 15 минут). Начать B нужно в течение 24 часов
после сдачи A. Вариант выбирает сервер. Решение отправляется явно; высокий
общий балл не компенсирует невыполненные обязательные требования.

Подробный маршрут проверки — в [руководстве, глава 10](docs/submission/01_jury_guide.pdf).

## Автономная проверка подбора

`app.tools.matching_check` рассчитывает B0/B1/B2 общим с API кодом.
Он не подключается к БД, почте или runner и не изменяет продуктовые данные.
Labels используются только после построения выдачи. При неполной разметке
метрики соответствующей потребности обозначаются «не измерено».

Готовая инструкция запуска образа без сети — в
[руководстве, глава 09](docs/submission/01_jury_guide.pdf).
[Схемы и словарь](docs/release/cli-input/README.md),
[сохранённый контрольный отчёт](docs/release/technical/v3-cli/report.md).
На выходе: `rankings.json`, `metrics.json`, `report.md`, `run_manifest.json`.

## Как устроено и что проверено

React **19.2.0** и TypeScript **5.9.3**, сборка Vite **7.1.7**; сервер
FastAPI **0.142.2** на Python **3.14.4**, продуктовая БД PostgreSQL **17**.
Решения Python и SQL исполняются отдельно; SQL-среда — PostgreSQL **18**.
API не имеет доступа к Docker socket. Версии библиотек и все **83 операции
на 70 путях** приведены в PDF; точные зависимости закреплены в `uv.lock`
и `frontend/package-lock.json`.

Оформление использует официальный логотип ФСП и локальные JetBrains Mono /
TDAText с кириллицей. [Источники и лицензии](frontend/src/assets/brand/README.md)
сохранены; в приложении лицензии доступны по `/assets/licenses/fsp/`.

В журнале 10–11.10.2026 зафиксированы: основной backend-пакет **400 passed**,
регрессии наполнения **5 passed**, полный прогон v3 **28 764 проверки** без
технических ошибок, чистый Compose с миграциями и браузерные сценарии обеих
ролей. Интерфейс проверен на компьютере, планшете и телефоне; сохранён 101 снимок.
Ruff, mypy, ESLint, TypeScript, Vite и Docker-сборки прошли соответствующие пакеты.
Это результаты выполненных ранее проверок; подготовка документов их не повторяет.

Банк и методика v3 проверены людьми и приняты пользователем. Допуск по реальным
хешам сохранён. Синтетические метрики подбора не доказывают качество реального
найма; отсутствующие численные показатели точности и сопоставимости не заявляются.
ФСП подключён через тестовый адаптер, а не боевой реестр или настоящий FSP ID.
Контейнерная изоляция `docker-limited` имеет общее ядро с хостом и не эквивалентна
VM/gVisor. Приложение не объявляется production-ready.

Фактические результаты и история: [журнал исполнения](docs/07_execution_plan.md).
[Прежние материалы выпуска](docs/release/README.md) сохранены как история;

## Если запуск не завершился

Посмотрите состояние и последние сообщения:

```bash
docker compose ps
docker compose logs --tail=80 api worker populate
```

Если порты заняты, запустите отдельный проект на свободных портах и подсетях
по инструкции в PDF, глава 02. Не удаляйте чужие контейнеры и не выполняйте
`docker compose down -v`: эта команда удаляет данные БД.
