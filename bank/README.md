# Экспериментальный банк Backend Junior/Middle

`blueprints.json` — фиксированная матрица X/Y: по 4 A + 2 B.
`private/full.json` — 12 семейств × два грейда, условия, отдельные действия и
рубрики навыков, эталоны, альтернативы, ошибки, параметры и перенос.
`private/stage1.json` сохранён как историческая поставка X1/X4 этапа 1.
`vacancy_mappings.json` и `vacancy_mappings.md` — три трассировки требований
вакансий. Во всех примерах сохраняется полная стандартная форма.
Не раздавать каталог через API, static-files или PDF кандидата.

Технический прогон: `python -m app.tools.bank_quality --output /tmp/bank-report`.
Python исполняется только через настроенный mTLS runner. При недоступности
runner отчёт имеет статус `incomplete`, ни одна Python-версия не допускается.
Один успешный технический отчёт не заменяет взаимную проверку материалов
двумя участниками команды и не доказывает сопоставимость сложности на людях.

Для X4 и Y4 подготовлены два правильных решения и три класса ошибок на грейд.
Кандидат задаёт 2–3 JSON-случая; произвольный тестовый код не принимается.
X4: обязательны остановка после первой страницы и дубли записей;
дополнительный — запрос после завершения. Y4: обязательны повтор после успеха
и неповторяемой ошибки; дополнительный — превышение лимита попыток.
Контракты и ограничения отдельно заданы в `test_policy.input_contract`.
Результат входит в рубрику
связанного навыка; отдельного бонуса и дополнительных доказательств нет.

SQL/data-ответ содержит результаты и структурированные признаки семантики:
альтернативные запросные планы, порядок, NULL, зависимости, транзакции.
Оценка не сравнивает текст SQL с одной эталонной строкой; свободный SQL не
исполняется. Эталоны Python запускаются только в docker-limited runner.

`report.json` — служебный отчёт с ожидаемыми/фактическими результатами,
версиями, хешами и ошибками. Для публикации предназначен только
`public-summary.json`: в нём нет решений, рубрик, входов и содержания B.
Безопасная демонстрация механизма: тест с неверным ожидаемым ответом
отвергает правильную реализацию и не выполняет обязательные требования;
подготовленные закрытые входы для объяснения публиковать не требуется.

Технический успех CLI (код 0) не означает зачётный допуск: пока независимое
review не проведено, `admission_status=not_admitted`. Реальное review
записывается отдельно списком `ReviewRecord` с reviewer, author, reviewed_at
(ISO 8601 с timezone), bank_hash, blueprint_hash, mappings_hash, decision и
evidence. Автор не может выступать своим рецензентом. Отсутствующее review
нельзя заменять фиктивной записью. Для обязательного контроля:
`python -m app.tools.bank_quality --output /tmp/reviewed-bank --reviews /path/to/reviews.json --require-admission`.

Перед использованием сохранённого отчёта вызывается `require_admission`:
проверяются фактические байты банка, матрицы, трассировок, версия и хеш
оценщиков, полнота результатов всех 24 версий и независимое review.
Любое изменение требует нового отчёта; прежние файлы/отчёты сохраняются
для старых циклов. Выдача попыток, история показов и assessment runtime — этап 4.
