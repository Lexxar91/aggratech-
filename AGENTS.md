## Порядок реализации и проверок

- Единица работы — согласованный законченный этап, а не отдельная функция.
- Реализуй этап целиком без запросов подтверждения после каждого файла.
- Нужные тесты можно писать вместе с реализацией.
- Не запускай тесты, lint, typecheck и сборку после каждой функции
  или каждого сохранения файла.
- После завершения реализации выполни согласованный пакет проверок:
  тесты затронутого поведения, необходимые интеграционные проверки,
  lint/typecheck и сборку, если они относятся к этапу.
- Не повторяй успешную проверку без изменений, способных повлиять
  на её результат.
- После исправления ошибки повтори проваленную проверку и проверки
  поведения, затронутого исправлением.
- Проверенный результат должен относиться к окончательной версии кода.
- Досрочный диагностический запуск допустим, если он снимает конкретный
  блокер: совместимость зависимостей, запуск контейнера или изоляция.
  Кратко объясни причину.
- Не заменяй обязательные проверки обещанием выполнить их позже.
- После выполнения Definition of Done обнови журнал исполнения
  и остановись. Не переходи к следующему этапу самостоятельно.
- Не выполняй commit и push без отдельного запроса.
