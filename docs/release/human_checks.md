## 2. Малый assessment-пилот и сравнение форм

Цель — четыре добровольца вне команды, по два на Junior и Middle;
если есть только два, записать фактический недобор. Нужны два компетентных
разметчика уровня **до просмотра баллов системы**, отдельный рабочий пример
или интервью вне зачётных семейств, информированное согласие и псевдонимы.
Стаж и самооценка не являются единственным эталоном.

Сначала завершить review/допуск. Затем каждый человек проходит X и Y на одном
заявленном грейде; порядок X→Y/Y→X по возможности уравновесить. Форма определяется
приложением, а не редактированием БД. Один цикл — A до 30 минут и B до 15 минут;
B открывается сразу после A, начать её нужно за 24 часа. Весь пилот — до 90 минут
активной работы плюс реальные интервалы. Не раскрывать ответы до двух циклов.

В обычном аккаунте второй цикл того же грейда доступен через **7 суток**;
два завершённых цикла за 30 суток. Планировать две встречи с соблюдением cooldown,
фиксируя фактический порядок форм. Не менять часы, не помечать человеческую
попытку техническим сбоем и не создавать двойника ради обхода календаря.
Отдельного исследовательского режима нет; ускоренный пилот сейчас не подготовлен.
Противоположный грейд не является повторяемостью X/Y одного уровня.

Записать в закрытый журнал: псевдоним, грейд, независимые предварительные оценки
и аргументы двух разметчиков, расхождения/неопределённость; ID циклов, версии
материалов и оценщика, порядок, начало/конец A/B, помощь, усталость, обучение,
сбои, неясные формулировки и пограничные случаи. Для X4/Y4 отдельно время,
ошибки формата и выявленные классы. Недоопределённый уровень не включать в accuracy.

Первый полный контрольный цикл — для confusion matrix по каждому грейду;
второй — для повторяемости, не выбирать лучший. Рассчитать ошибочное подтверждение
и отказ с указанными знаменателями, Wilson 95%, согласие X/Y, разницу по навыкам
и пересечения границ. По семействам D = успех сильной группы − успех слабой
с предварительным эталоном; при малом n только диагностика. Цели ≤5%, ≤10%, ≥85%
не являются достигнутыми значениями. Объективность и сопоставимая сложность
**не измерены** до получения данных; малый пилот не доказывает отраслевую точность.

Если исследуются утечка/AI/помощник, заранее разделить режимы без утечки,
утечки вариантов и семейств; учитывать одинаковое время подготовки и размер
банка. Моделируемые атаки не считать людьми и не доказывать причинное превосходство.
После правок использованные для разработки люди не становятся контрольными
для новой версии без отдельной контрольной выборки.

## 3. Matching: слепая разметка и объяснения

Нужны **два разметчика**, автор алгоритма не может быть единственным.
Выдать паспорт, `control.dataset.json` (80 кандидатов/8 потребностей),
`labeling.schema.json`, пустой human-template и руководство
`fixtures/validation/README.md`. До фиксации исходных оценок **не выдавать**
rankings, metrics, synthetic labels и слайды с результатами B0/B1/B2.
Набор искусственный; человеческая разметка этого набора не делает его реальным наймом.

Разметить весь допустимый пул каждой потребности, не только top-20;
eligibility отдельно от relevance 0/1/2/3. Приватность, допустимый грейд и известные
несовместимости учитывать; неизвестные существенные условия — отдельная группа
уточнения, а не пониженная квалификация. Требовать краткое основание каждой оценки.
Оба разметчика сохраняют исходники независимо; после фиксации составить разногласия
и согласованный labels без перезаписи оригиналов. Нерешённую пару не заменять нулём.

Запустить B0/B1/B2 по одному `as_of` без изменения весов. Для неполной потребности
все её метрики — «не измерено». Показать все восемь значений и парные разности,
